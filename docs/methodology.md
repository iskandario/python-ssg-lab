# Методика эксперимента

## Исследовательский вопрос

Какие архитектурные решения позволяют сохранить корректный результат конкурентных торгов, привести веб-клиенты к актуальному состоянию после разрыва и доставить причинно связанное уведомление при закрытом Telegram Mini App?

## Гипотезы

**H1.** Транзакционная обработка ставки и идемпотентный ключ `(auctionId, commandId)` сохраняют правильную цену и победителя при конкурентных запросах.

**H2.** В непрерывном соединении SSE и WebSocket дают меньшую p95-задержку live-доставки, чем HTTP polling.

**H3.** Монотонные версии и replay после reconnect приводят клиентов к финальной серверной версии без итоговых пропусков.

**H4.** Hybrid recovery возвращает то же состояние, что snapshot/replay, и выбирает меньший сериализованный JSON payload.

**H5.** Durable inbox Mini App и Telegram Bot fallback обеспечивают получение уведомления без потери, повторного показа и нарушения причинного порядка.

## Управляемые факторы

| Фактор | Уровни |
|---|---|
| Вид торгов | прямой, обратный |
| Транспорт | Polling, SSE, WebSocket |
| Клиентов на транспорт | 2, 5, 10 |
| Исходных ставок | 24, 48, 96 |
| Параллельность команд | 4, 8, 24 |
| Polling interval | 250, 500, 1000 мс |
| Дополнительная задержка | 20, 120, 300 мс |
| Jitter | 10, 80, 200 мс |
| Разрыв канала | нет, 800, 1400 мс |
| Повторные команды | 10, 15, 20 % |
